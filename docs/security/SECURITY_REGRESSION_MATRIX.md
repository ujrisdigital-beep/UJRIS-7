# Security regression matrix (Step 2A)

Maps Codex Step 1 findings to the Step 2A fix, the automated test that
guards it, residual risk, and the intended Supabase-era replacement.

This matrix does **not** claim production readiness.

| Codex finding | Implementation fix | Automated test | Residual risk | Future Supabase replacement |
|---|---|---|---|---|
| 1. Evidence served as active HTML on the app origin | `buildEvidenceDownloadHeaders`: always `Content-Disposition: attachment`, `X-Content-Type-Options: nosniff`, force `application/octet-stream` for HTML/SVG/JS (declared or sniffed). Path containment in `resolveContainedEvidencePath`. Filename sanitised for `Content-Disposition`. | `tests/security/evidence-delivery.test.ts` | Preview of PDF/images on-origin is still forbidden in this ticket; a future preview feature could reintroduce XSS if inlined. Sniffing only inspects the first 2KB. | Private bucket + signed URLs with `Content-Disposition: attachment` and a non-app download host if preview is required. |
| 2. Authentication lacks rate limits | Interim in-memory limiter (`src/lib/rate-limit.ts`), 5 attempts / 15 minutes, keyed by normalised email, applied in `loginAction` / `signupAction` **before** user lookup. Generic messages. Fail-open if the store throws. | `tests/security/rate-limit.test.ts` | Single-process only; resets on restart; not shared across instances; IP rotation still possible; fail-open under store failure. No password-reset endpoint exists yet. | Supabase Auth rate limits + WAF / edge limiter + shared store. Do not keep this Map. |
| 3. Logout does not revoke captured session tokens | JWT `jti` bound to `AuthSession` row. `verifySessionToken` requires unrevoked, unexpired row. `logoutAction` sets `revokedAt`. Tokens are not stored in plaintext. | `tests/security/session-revocation.test.ts` | Edge middleware still only checks cookie *presence*. Stolen JWT works until logout/expiry on this instance’s DB. No global “logout all devices” UI. | Supabase Auth session revocation / refresh-token rotation. Drop `AuthSession`. |
| 4. Deadline inference can choose the wrong date and suppress urgency | `inferLimitationStart`: confirmed / provisional / ambiguous / insufficient_data. Multiple calendar days → `ambiguous`, earliest used only as a warning. `higherUrgency` so uncertainty cannot downgrade a stronger signal. Gateway no longer picks the latest date. | `tests/unit/date-inference.test.ts` | Heuristic date extraction can still miss or mis-parse UK written dates. Earliest date can overstate urgency. Not legal advice. | Same tests against the future pipeline; still no LLM deadline arithmetic. |
| 5. Billing fallback grants paid plans when Stripe is absent | Fail-closed: missing Stripe → no paid entitlement. `UJRIS_ALLOW_DEV_BILLING=true` only when `NODE_ENV !== production`. Plan ids validated server-side (`isPlanId`). | `tests/unit/billing-mode.test.ts` | If someone sets the flag in a mislabelled non-production deploy, simulated paid access is possible. `User.plan` remains a writable column until Stripe is SoT. | Stripe webhooks as sole paid writer; Supabase RLS; remove `activateDevModeSubscription`. |
| 6a. Evidence + custody not atomic | `persistEvidenceWithCustody` uses `db.$transaction`. File deleted only if the evidence row was not committed. | `tests/integration/evidence-integrity.test.ts` | Disk write still happens before the transaction (orphan files possible; not orphan *rows*). SQLite tx is not distributed. | Postgres transaction + storage object in the same workflow (upload → hash → insert → confirm); object delete on rollback. |
| 6b. Hash “verified” merely because a hash exists | `verifyEvidenceIntegrity` recomputes SHA-256 of current bytes vs stored original. Never writes `sha256`. | same file | “verified” is byte-identity, not authenticity. Missing file → `unavailable`. | Same function over object-storage GET; store original hash in an immutable column. |
| 7. Dormant exported helper lacks ownership checks | `refreshCaseIntelligenceForOwner(userId, caseId)` refuses non-owners. Server action requires `getCurrentUser()`. | `tests/integration/ownership.test.ts` | Other helpers must keep the same pattern. No RLS yet — every query still relies on application checks. | Postgres RLS: `case.user_id = auth.uid()`. Keep the test. |
| 8. No automated tests / CI | Vitest unit/integration/security, Playwright smoke, GitHub Actions (`npm ci`, typecheck, lint, tests, build) + `npm audit`. | `npm run test`, `.github/workflows/ci.yml` | E2E is smoke-only and not in default CI (needs Playwright browsers). Audit may fail on upstream Prisma advisories we cannot safely bump. | Re-run the same scripts against Supabase test project. |
| 9. Forensic findings lack structured provenance | Design only: `docs/architecture/FORENSIC_DOCUMENT_INSPECTOR.md`. | n/a (design) | Runtime findings remain a JSON blob on `Evidence`. | Implement designed tables after evidence migration. |
| 10. AI outputs lack grounding / cost monitoring | Out of scope (no UJU expansion). | none | Ungrounded phrasing and unbounded LLM cost remain if `OPENAI_API_KEY` is set. | Separate ticket: usage table, grounding checks, budget caps. |
| 11. Reversed timestamp produced incorrect “later” finding | Rule F-TS-001 in `evaluateTimestampAnomaly`: “later revision appears present” only if modified is **after** created by >24h. Reversed pair → `timestamp_inconsistency`. No forged/fraud language. Timezone-equivalent instants produce no finding. | `tests/unit/forensic-timestamps.test.ts` | 24h threshold is a product choice, not a legal standard. EXIF/PDF clocks are often wrong. | Same rule_id on `forensic_findings`; do not reintroduce `Math.abs` for this comparison. |

## Interim controls (must not be described as production-grade)

- In-memory auth rate limiter
- Custom JWT + `AuthSession` revocation
- Local disk evidence storage
- SQLite (no RLS)
- Optional non-production billing simulation flag
